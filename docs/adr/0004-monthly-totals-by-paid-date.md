# ADR-0004: 月の集計と予算は支払日で数え、利用日も記録に残す

- 状態: 採用
- 日付: 2026-10-14

## 背景

記録の日付は `occurred_date`（「支払った日」）の1つだけだった。
カードでは、使った日（利用日）と口座からお金が出ていく日（支払日）が1〜2か月離れる。
どちらの日付で月を数えるかによって、「今月あといくら」の意味が変わる。

家計簿で見たいのは「今月いくら入って、今月いくら出ていくか」である。
これは口座の動きであり、カードの分は引き落とされる月の支出として数える必要がある。

一方、自動取り込みの元になる利用通知メールに載っているのは利用日だけで、支払日は載っていない。

## 選択肢

1. 利用日だけを記録し、月も利用日で数える
2. 支払日だけを記録し、月も支払日で数える
3. 利用日と支払日を両方記録する。支払日は支払い手段の締め日のルールから自動で計算し、月は支払日で、週は利用日で数える

## 決定

3 を採用する。

- 記録には利用日（`occurred_date`）と支払日（`paid_date`）を両方持つ。
- 支払日は、記録するときに支払い手段ごとの締め日・引き落とし日のルールから計算する。現金と即時に引き落とされる決済では利用日と同じ日にする。
- 月の予算・月の支出合計・月のまとめ・予算の到達は、**支払日** が属する月で数える。
- 週のまとめは、**利用日** が属する週で数える。「その週に何に使ったか」を振り返るためのものであり、支払日で数えると引き落とし日のある週に支出がまとめて出てしまうためである。

## 結果

- 「今月あと〇円」が、今月口座から出ていくお金の見通しと一致する。収入と並べれば、月の入りと出を比べられる（収入の記録は → [ADR-0005](./0005-income-manual-entry-from-app.md)）。
- 支払日を計算で決めるので、自分で入力する日付は増えない。カードごとに締め日のルールを一度設定するだけで済む。
- 利用日を残すので、週の振り返りや明細の並びは使った順のまま見られる。2つ目の日付をあとから復元する必要もない。
- カードで使った分は、使った月の予算ではなく引き落とされる月の予算から引かれる。使いすぎに今月の予算の残りで気づくことはできない。そのため、予算の到達は今月以降のすべての月で判定し、どの月の予算かを通知に書く。
- 計算どおりにならない支払いがある。どれも、気づいたときにアプリで支払日を直す。
  - 引き落とし日が土日祝に当たり、翌営業日にずれるもの。祝日による繰り延べは計算しない（月末が引き落とし日のカードでは月をまたぐことがある。→ 残課題 R-10）
  - 加盟店の売上確定が遅れ、次の締めに回るもの
- 分割払い・ボーナス払い・リボ払いは扱わない。すべて1回払いとして計算する。
  （→ スキップ・分割・リボ払いは [ADR-0011](./0011-card-payment-plans.md) で扱うことにした。ボーナス払いは引き続き扱わない）
