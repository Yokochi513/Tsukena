# ADR-0007: Discord bot は REST API を通してだけ記録を読み書きする

- 状態: 採用（bot 用のエンドポイントの入力・出力は API 一覧で決める）
- 日付: 2026-10-19

## 背景

[ADR-0006](./0006-separate-api-and-bot-processes.md) では、REST API と、Discord bot＋定期実行を別のプロセスで起動し、どちらもサービス層を import して同じ SQLite のファイルに書き込むと決めた。

この形では、DB に書き込むプロセスが2つになる。
[ADR-0001](./0001-self-hosted-sqlite.md) で得ていた「書き込み元が1つなので SQLite のロック競合を考えなくてよい」が成り立たず、WAL モードとロック待ちに頼ることになる。
また、bot のプロセスがサービス層・repository・DB のファイルの場所まで知ることになり、Discord との変換役にとどまらない。

DB を読み書きする入口を、REST API の1つにまとめたい。

## 選択肢

1. 1つのプロセスに同居させる（ADR-0001 の当初の形）
2. 別のプロセスで起動し、どちらもサービス層を import して同じ SQLite のファイルに書き込む（ADR-0006）
3. 別のプロセスで起動し、bot は REST API を HTTP で呼んで記録を読み書きする。DB を開くのは API のプロセスだけにする

## 決定

3 を採用し、ADR-0006 を置き換える。

- **DB を開くのは API のプロセスだけ**とする。bot のプロセスは、サービス層・repository・DB のファイルを import も参照もしない。
- 起動の入口は ADR-0006 と同じく2つ持つ。REST API は `python -m tsukena.api`、Discord bot は `python -m tsukena.bot` で起動する。
- **定期実行（`scheduler`）は API のプロセスに移す。** Gmail の取り込みは DB に書き込むため、DB を開くプロセスで動かす。
- 定期実行の通知（取り込めないメール・予算の到達・週と月のまとめ）は、API のプロセスの通知（`notifier`）が、Discord の HTTP の API に bot のトークンで送る。Discord への常時接続（Gateway）は bot のプロセスだけが持つ。
- bot は、現金の記録と、リアクションによるカテゴリの変更を、REST API で行う。
  - 現金の記録には、bot だけが呼べるエンドポイントを足す。応答には、返事に要る記録の結果（カテゴリ・今月の残り・新たに超えた閾値）を含める。
  - リアクションから記録を探すため、重複排除キーで記録を引く手段を足す。
  - カテゴリの変更は、アプリと同じ `PATCH /transactions/{id}` を使う。
- **トークンを2つに分ける。** スマホアプリ用と bot 用の Bearer トークンをサーバーの設定に持ち、現金の記録のエンドポイントは bot 用のトークンでしか受け付けない。スマホアプリから支出を追加できない方針（→ [design.md 4.3](../design.md#43-スマホアプリ修正確認待ち振り返り収入)）を、API の側で守るためである。
- 現金の記録で予算の閾値を超えたときの通知は、これまでどおり bot が返事の後に送る。返事より先に通知が届かないようにするためである。自動取り込みで超えたときは、API のプロセスの通知が送る。
- bot から API を呼ぶ HTTP のクライアントには `aiohttp` を使う。`discord.py` が依存しているため、新しい依存は増えない。

## 結果

- DB に書き込むのが API のプロセスだけになり、ADR-0001 の「SQLite のロック競合を考えなくてよい」がプロセスの間では再び成り立つ。
- 記録のルール（支払日の計算・分類・重複排除・予算の判定・ルールの学習）を通る入口が REST API の1つになる。入口によって振る舞いがずれる余地が、ADR-0006 より小さい。
- bot は Discord と REST API の間の変換だけを受け持つ。別のマシンで動かすことも、別の入口（Discord 以外のチャットなど）を足すことも、API を呼ぶ側を足すだけで済む。
- API が止まっている間、bot は記録できない。bot は記録できなかったことを返事で知らせ、Discord に一言送り直してもらう。
- bot 用のエンドポイントと、トークンの区別が増える。入力・出力・エラーは [api_list.md](../api_list.md) に足す。
- bot から API への通信の分だけ、記録の返事が遅くなる。同じ機械の中の通信なので、利用者が気づく差にはならないとみなす。
- 通知を送るプロセスが2つになる（現金の予算の到達は bot、それ以外は API）。どちらも同じ bot のトークンで送るので、Discord の上では同じ bot からの通知に見える。
