# ADR-0011: カードの支払い方法（スキップ・分割・リボ払い）を記録し、月の集計を引き落とし額に合わせる

- 状態: 採用
- 日付: 2026-10-28

## 背景

[ADR-0004](./0004-monthly-totals-by-paid-date.md) では、分割払い・ボーナス払い・リボ払いを扱わず、すべて1回払いとして支払日を計算すると決めた。

JCB では、1回払いで使った分を、あとから次の支払い方法に変えられる（MyJCB の「あとから分割」「あとからリボ」「ショッピングスキップ払い」）。

- スキップ払い: 支払い月を 1〜6 か月先に送り、その月に元金と手数料（金額 × 月利 × 送った月数）を1回で払う
- 分割払い: 3〜60 回に分け、毎月、元金と手数料を払う。初回の手数料は締め日の翌日から引き落とし日までの日割りになり、最終回で端数を調整する
- リボ払い: リボにした利用分を1つの残高にまとめ、毎月、決まった元金（定額コース）と残高にかかる手数料（年率 × 日数 ÷ 365）を払う

支払い方法を変えた支出も1回払いとして数えると、月の支出がカードの引き落とし額と合わない。手数料も、どの月の支出にも入らない。
月の集計で見たいのは「今月口座から出ていくお金」なので、引き落とし額と一致させたい。

## 選択肢

支払い方法を変えた支出の、月ごとの額の決め方:

1. カード会社の式で、回ごとの元金と手数料を計算するだけにする
2. 明細に載る数字（回数と手数料の総額）を入力し、回ごとに割り振る
3. カード会社の式で計算し、明細と違う回だけ手で直せるようにする

リボ払いの手数料の計算:

- A. 支出ごとに、その支出だけを残高として計算する
- B. 同じカードのリボ払いの支出をまとめて1つの残高にし、カードの請求と同じ単位で計算する

## 決定

3 と B を採用する。

- 支出に支払い方法（`payment_plan`: `lump` / `skip` / `installment` / `revolving`）と、スキップの月数・分割の回数（`plan_count`）を持つ。
- 1回払い以外の支出は、回ごとの引き落とし（`charges`: 引き落とし日・元金・手数料）を持つ。支出の `paid_date` は「1回払いだったときの支払日」のまま残し、予定を計算する起点にする。
- 月の支出・カテゴリの内訳・月で絞った明細は、1回払いなら支払日、ほかの支払い方法ならその月の引き落とし（元金と手数料の合計）で数える。手数料は元の支出のカテゴリに入れる。
- 回ごとの額はカード会社の式で計算する（式は → [design.md 7.2](../design.md)）。明細と違う回は、アプリで引き落とし額を入れて直す。元金は変えず、差を手数料にする。
- リボ払いは、支払い手段ごとにリボ払いの支出を全部まとめて、残高が無くなるまで毎月の引き落としを計算する。元金は古い支出から充て、手数料は支出ごとの残高と日数に比例して振り分ける。リボの手数料は支払い手段と月で直す（`revolving_fees`）。
- 手数料率とリボの元金は、カードごとに設定ファイルに書く（`fee_rate`, `revolving_principal`）。書いていないカードと即時の支払い手段では、支払い方法を変えられない。

## 結果

- 月の支出が、カードの引き落とし額と一致する。計算でずれた回も、明細を見て直せば一致する。
- 分割やリボで払っている間は、引き落としのある毎月の明細に同じ支出が出る。金額は、その月の1回分を出す。
- リボは、同じカードで別の支出をリボにしたり、やめたり、消したりするたびに、そのカードのリボ全体を計算し直す。引き落としの元金と手数料の割り振りも変わる。
- 金額や支払日を直すと、その支出の予定を作り直す。手で直した手数料は消える（リボで月ごとに直した手数料は残る）。
- 週のまとめは、これまでどおり利用日の支出の金額で数え、手数料は入れない。
- 引き落とし日の土日祝による繰り延べは、ここでも計算しない（→ 残課題 R-10）。日割りの日数がずれた回は、手数料を直す。
- ボーナス払いは、まだ扱わない。
- 手数料率は1つしか持てない。JCB では 2026年10月1日の利用分から 18.00% に変わったため、それより前の支出の手数料は明細を見て直す。
