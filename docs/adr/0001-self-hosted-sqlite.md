# ADR-0001: 自宅サーバー／VPS に常駐させ、SQLite に保存する

- 状態: 採用
- 日付: 2026-09-30

## 背景

Gmail の定期取り込み、Discord bot の常時接続、定期通知、スマホアプリ向け API を動かす場所と、データの保存先を決める必要があった（README「未決定」）。

## 選択肢

1. Google Cloud（Cloud Run + Firestore + Cloud Scheduler）
2. 自宅サーバー／VPS に常駐させ、SQLite に保存する
3. Supabase などの BaaS とサーバーレス関数

## 決定

2 を採用する。サーバーは1プロセスで常駐させ、Discord bot・REST API・定期実行を同居させる。保存先は SQLite の1ファイルとする。

## 結果

- Discord bot の常時接続（WebSocket）をそのまま持てる。サーバーレスで常時接続を保つ工夫が要らない。
- 書き込み元が1プロセスに限られるため、SQLite のロック競合を考えなくてよい。
- クラウドの課金やサービスの仕様変更に左右されない。
- その代わり、次を自分で面倒を見る必要がある。基本設計の残課題として扱う。
  - スマホアプリから API に届く経路（R-1）
  - バックアップ（R-2）
  - プロセスの常駐と再起動（systemd など）
